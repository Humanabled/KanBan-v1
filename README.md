# Diferencias entre Kanban y Scrum

## 1. ¿Qué es Kanban?

Kanban es un método para gestionar y mejorar el flujo de trabajo. Hace visible el trabajo mediante un tablero dividido en estados (por ejemplo, **To Do**, **In Progress**, **Review** y **Done**). Cada tarea se representa con una tarjeta que avanza por el flujo.

Prácticas habituales:
- Visualizar el trabajo y las fases del proceso.
- Limitar el trabajo en curso (**WIP, Work In Progress**) para evitar empezar demasiadas tareas a la vez.
- Gestionar el flujo y detectar bloqueos o cuellos de botella.
- Establecer políticas explícitas para saber cuándo una tarea puede pasar de columna.
- Incorporar ciclos de feedback y mejorar el proceso continuamente.

Kanban no exige Sprints ni roles específicos. El equipo puede empezar visualizando su proceso actual y mejorarlo progresivamente.

## 2. ¿Qué es Scrum?

Scrum es un marco de trabajo ágil basado en el empirismo y el pensamiento Lean. Organiza el trabajo en Sprints de duración fija, con un objetivo para cada Sprint y responsabilidades definidas:
- **Product Owner:** maximiza el valor del producto y gestiona eficazmente el Product Backlog.
- **Scrum Master:** ayuda a establecer Scrum y a mejorar la efectividad del equipo.
- **Developers:** crean un Increment utilizable y mantienen la calidad.

Incluye Sprint Planning, Daily Scrum, Sprint Review y Sprint Retrospective dentro del Sprint.

## 3. Comparación

| Aspecto | Kanban | Scrum |
|---|---|---|
| Enfoque | Mejorar el flujo de trabajo existente | Entregar valor mediante Sprints e inspección y adaptación |
| Organización temporal | Flujo continuo; no exige iteraciones fijas | Sprints de un mes o menos |
| Roles | No prescribe roles obligatorios | Product Owner, Scrum Master y Developers |
| Planificación | Continua, según capacidad y prioridades | Sprint Planning al inicio de cada Sprint |
| Entrega | Los elementos se entregan cuando están terminados | Se busca crear un Increment utilizable en cada Sprint |
| Cambios de prioridad | Se introducen según las políticas y capacidad del flujo | Se protege el Sprint Goal; el alcance puede aclararse y renegociarse |
| Control del trabajo | Límites WIP y métricas de flujo | Sprint Goal, Sprint Backlog e inspección en eventos |
| Reuniones | Se adaptan al contexto; no hay ceremonias obligatorias | Eventos definidos por Scrum |
| Mejora | Continua y evolutiva | Inspección y adaptación, incluida la Retrospective |

## 4. Ventajas

### Kanban
- Visualiza quién está haciendo qué y dónde se acumula el trabajo.
- Permite detectar bloqueos y cuellos de botella.
- Los límites WIP ayudan a reducir la multitarea.
- Se puede implantar gradualmente.
- Es útil cuando llegan tareas continuamente, como incidencias o soporte.

### Scrum
- Proporciona un ritmo de trabajo y objetivos a corto plazo.
- Define responsabilidades y momentos de colaboración.
- Facilita recibir feedback frecuente de interesados.
- La Sprint Retrospective impulsa mejoras del equipo.
- Ayuda a mantener el foco mediante el Sprint Goal.

## 5. ¿Cuándo conviene utilizar cada uno?

**Kanban** puede ser adecuado para un equipo de soporte técnico que recibe incidencias continuamente. Las tarjetas muestran el estado y un límite WIP evita acumular demasiadas tareas abiertas.

**Scrum** puede encajar en un equipo que desarrolla una nueva aplicación y necesita trabajar por objetivos periódicos, revisar incrementos con usuarios y adaptar el producto al final de cada Sprint.

También es posible combinar prácticas de ambos enfoques, siempre que el equipo entienda qué reglas está utilizando y no confunda sus conceptos.

## Conclusión

Kanban se centra en visualizar y optimizar el flujo continuo de trabajo; Scrum estructura el trabajo en Sprints con responsabilidades, eventos y artefactos definidos. No existe un método universalmente mejor: la elección depende del tipo de trabajo, la estabilidad de las prioridades y las necesidades del equipo.
